Baseline's visual identity lives entirely inside the inline `<style>` block at the top of `index.html`. There is no separate design-token file, no Tailwind config, and no CSS-in-JS runtime — every decision is expressed as plain CSS, readable and editable without tooling. This page documents that system from the ground up.

---

## CSS custom properties

The entire colour and shape vocabulary is declared on `:root`:

```css
:root {
  --background: #ffffff; --foreground: #0a0a0a;
  --brand: #2563c9; --brand-deep: #0f2f63; --brand-light: #5790e6;
  --accent-teal: #0b6e97; --surface: #f4f4f4; --surface-card: #ffffff;
  --ink: #0a0a0a; --ink-soft: #717784; --ghost: #d7dae1; --hairline: #e6e8ec;
  --on-brand: #ffffff;
  --radius-card: 1.5rem; --radius-card-lg: 2rem; --radius-pill: 62.5rem;
}
```

### Color tokens

#### Brand palette

| Token | Value | Usage |
|---|---|---|
| `--brand` | `#2563c9` | Primary interactive blue — focus rings, `.eyebrow` dot, `.pill.solid` hover, testimonial quotation mark. |
| `--brand-deep` | `#0f2f63` | Deep navy — hero background, stats section, footer background, overlay backdrops. |
| `--brand-light` | `#5790e6` | Lighter blue — focus outline, hover state for `.pill.light`, active carousel dot (light theme). |
| `--accent-teal` | `#0b6e97` | Teal accent — `court-cap.blue` caption overlay. Not used in component classes directly; available for custom use. |

#### Surface tokens

| Token | Value | Usage |
|---|---|---|
| `--surface` | `#f4f4f4` | Off-white background for `#programs` section, `.pct` badge, `.badge-card`, `.tcard`, `.success`, `.iconbtn`. |
| `--surface-card` | `#ffffff` | Pure white for the modal panel background — keeps the modal visually distinct from `--surface` elements. |
| `--background` | `#ffffff` | Page-level background; also used as the background of `<input>` and `<textarea>` fields. |

#### Ink tokens

| Token | Value | Usage |
|---|---|---|
| `--ink` | `#0a0a0a` | Near-black for body text, `.pill.solid` background, `.abtn.solid` background. |
| `--ink-soft` | `#717784` | Secondary text — descriptions, labels, footer muted copy. |
| `--ghost` | `#d7dae1` | Ghost-text heading in the `#trust` section; default state of dark-theme carousel dots. |
| `--hairline` | `#e6e8ec` | 1px divider lines — program rows, footer sections, testimonial card footers, `.abtn` border. |
| `--on-brand` | `#ffffff` | White text intended for placement on brand-colored backgrounds. Defined as a semantic alias rather than a raw value. |
| `--foreground` | `#0a0a0a` | Default `color` on `<body>`. Mirrors `--ink` but is the top-level cascade root. |

### Radius tokens

| Token | Value | Usage |
|---|---|---|
| `--radius-card` | `1.5rem` | Standard card corners — `.glass`, `.tcard`, `.coach`, `.badge-card`, `.modal-panel`, `.court`. |
| `--radius-card-lg` | `2rem` | Larger card corners — `.hero`, `.facilities`, `.stats`, `.foot` (the big rounded sections). |
| `--radius-pill` | `62.5rem` | A large fixed value that renders any element as a pill regardless of its height — `.pill`, `.abtn`, `.burger`, `.cdots i`, `.pct`, `.track`. |

## Fluid type scale

Rather than fixed breakpoint jumps, Baseline uses a viewport-relative root `font-size` so that `rem`-based values scale continuously as the window resizes.

```css
html { font-size: 16px }

@media (max-width: 1920px) { html { font-size: 0.833333vw } }
@media (max-width: 1440px) { html { font-size: 1.111111vw } }
@media (max-width: 1024px) { html { font-size: 1.5625vw  } }
@media (max-width: 640px)  { html { font-size: 4.444444vw } }
```

At each breakpoint, `1rem` equals a specific fraction of the viewport width:

| Breakpoint | `font-size` | `1rem` at breakpoint edge |
|---|---|---|
| ≤ 1920px | `0.833333vw` | ≈ 16px at 1920px wide |
| ≤ 1440px | `1.111111vw` | ≈ 16px at 1440px wide |
| ≤ 1024px | `1.5625vw` | ≈ 16px at 1024px wide |
| ≤ 640px | `4.444444vw` | ≈ 28px at 640px wide (mobile zoom) |

The fractions are calculated so that 1rem anchors near 16px at each breakpoint threshold, then grows proportionally until the next breakpoint catches it. Because almost every spacing value in the stylesheet is expressed in `rem`, the entire layout — padding, font sizes, border-radii, gap values — scales smoothly without separate `font-size` overrides at each breakpoint.

A secondary JS-side correction (`setRootFont`) handles very large viewports above 1920px by nudging the root font size up further, ensuring the layout doesn't cap out on wide monitors.

## Typography

### Typeface

**Onest** is loaded from Google Fonts at two weights:

```html
<link href="https://fonts.googleapis.com/css2?family=Onest:wght@400;500&display=swap"
      rel="stylesheet" />
```

It is applied to `<body>` with a system-font stack as fallback:

```css
body {
  font-family: "Onest", system-ui, sans-serif;
  font-weight: 400;
  -webkit-font-smoothing: antialiased;
}
```

`-webkit-font-smoothing: antialiased` removes sub-pixel rendering on macOS, giving Onest its intended thin-stroked appearance.

### Weight usage

| Weight | Class / context |
|---|---|
| `400` | Default body weight — descriptions, body copy, nav links. |
| `500` (`.med`) | Headings, labels, stats values, pill buttons, eyebrow text. Applied via `font-weight: 500` on specific selectors, or the utility class `.med`. |

## Component vocabulary

### `.pill` — button

The primary CTA button shape. Rendered as an `<a>`, `<button>`, or any inline element.

```css
.pill {
  display: inline-flex;
  align-items: center;
  gap: .5rem;
  border-radius: var(--radius-pill);
  padding: .875rem 1.75rem;
  font-size: .875rem;
  font-weight: 500;
  text-transform: uppercase;
  letter-spacing: .08em;
}
```

Three variants:

```css
.pill.light   { background: #fff; color: var(--brand-deep); }
.pill.light:hover { background: var(--brand-light); color: #fff; }

.pill.solid   { background: var(--ink); color: #fff; }
.pill.solid:hover { background: var(--brand-deep); }

.pill.outline { border: 1px solid currentColor; color: var(--ink); }
.pill.outline:hover { background: var(--ink); color: #fff; }
```

`.light` — white pill on dark backgrounds (hero, footer, mobile menu). `.solid` — ink-black pill on light backgrounds (testimonials Done button). `.outline` — bordered ghost button.

Any `.pill` containing an `<svg>` also gets a JavaScript-powered arrow nudge: on hover the icon translates 5px to the right via a spring (`tension: 320, friction: 20`).

### `.abtn` — icon button

Square icon buttons for carousel navigation arrows.

```css
.abtn {
  display: grid;
  place-items: center;
  width: 3rem;
  height: 3rem;
  border-radius: var(--radius-pill);
  border: 1px solid var(--hairline);
}
@media (min-width: 640px) { .abtn { width: 3.5rem; height: 3.5rem; } }

.abtn.outline { color: var(--ink); background: transparent; }
.abtn.outline:hover { border-color: var(--ink); }

.abtn.solid { background: var(--ink); border-color: var(--ink); color: #fff; }
.abtn.solid:hover { background: var(--brand-deep); }
```

`.outline` is the previous/secondary arrow; `.solid` is the primary next arrow. The inner SVG receives a spring-powered scale hover (`1 → 1.15`, tension 320, friction 18).

### `.eyebrow` — section label

A small uppercase label used to introduce each section.

```css
.eyebrow {
  display: inline-flex;
  align-items: center;
  gap: .5rem;
  font-size: .75rem;
  font-weight: 500;
  text-transform: uppercase;
  letter-spacing: .22em;
}
.eyebrow i {
  width: .375rem;
  height: .375rem;
  border-radius: var(--radius-pill);
  display: block;
}

.eyebrow.dark  { color: var(--ink-soft); }
.eyebrow.dark  i { background: var(--brand); }

.eyebrow.light { color: rgba(255,255,255,.7); }
.eyebrow.light i { background: var(--brand-light); }
```

The `<i>` element is a small filled circle that acts as a visual bullet. `.dark` is used on light-background sections; `.light` on the stats section, footer, and hero.

### `.glass` — glassmorphism card

Applied to the hero slider card and the membership stat widget.

```css
.glass {
  border-radius: var(--radius-card);
  border: 1px solid rgba(255,255,255,.15);
  background: rgba(255,255,255,.10);
  padding: .75rem;
  box-shadow: 0 1.25rem 2.5rem rgba(15,47,99,.2);
  backdrop-filter: blur(10px);
}
```

`backdrop-filter: blur(10px)` creates the frosted-glass effect against the hero image behind it. The semi-transparent white background and hairline border add definition without hiding the image.

---

### `.cdots` — carousel dots

Dot-row navigation used by both the hero slider and the coach carousel.

```css
.cdots { display: flex; gap: .5rem; align-items: center; }
.cdots button { padding: .375rem; }
.cdots i {
  display: block;
  height: .375rem;
  width: .375rem;
  border-radius: var(--radius-pill);
  transition: width .3s ease, background .3s ease;
}

/* Dark theme (on light backgrounds) */
.cdots.dark i { background: var(--ghost); }
.cdots.dark [aria-current="true"] i { background: var(--ink); width: 1.25rem; }

/* Light theme (on dark/image backgrounds) */
.cdots.light i { background: rgba(255,255,255,.4); }
.cdots.light [aria-current="true"] i { background: #fff; width: 1.25rem; }
```

The active dot widens from `0.375rem` to `1.25rem` with a CSS transition, creating a pill-shaped indicator. The `aria-current="true"` attribute is set by `renderDots()` in JavaScript on each slide change, which also provides the semantic active state for assistive technology.

---

### `.clip` / `.wfade` — animation reveal primitives

These two classes are the CSS half of the text reveal system. JavaScript wraps elements in them; the classes define the hidden start state.

```css
/* Word-clip reveal — used for headings */
.clip {
  display: inline-block;
  overflow: hidden;
  vertical-align: bottom;
  padding-bottom: 0.14em;
}
.clip > span {
  display: inline-block;
  transform: translateY(115%);
  opacity: 0;
  will-change: transform, opacity;
}
.clip.go > span {
  transform: translateY(0);
  opacity: 1;
}

/* Word-fade reveal — used for body copy */
.wfade {
  display: inline-block;
  transform: translateY(18px);
  opacity: 0;
}
.wfade.go {
  transform: translateY(0);
  opacity: 1;
}
```

`.clip` hides each word by clipping it below the visible area (`overflow: hidden` on the outer span, `translateY(115%)` on the inner). The `.go` class is the target state; the `transition` is written by `playClips()` in JavaScript with the correct duration and stagger. `.wfade` is a simpler fade-up used for paragraph text in the facilities section.

---

### `.sr-only` — screen-reader only

Standard visually-hidden utility. Used on `<dt>` elements in the stats grid to provide accessible labels without cluttering the visual layout.

```css
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0,0,0,0);
  white-space: nowrap;
  border: 0;
}
```

## Responsive strategy

### `<main>` padding inset

All seven sections sit inside `<main>`, which has a small padding on all sides:

```css
main {
  width: 100%;
  overflow-x: clip;
  padding: 0.5rem;
}
@media (min-width: 640px) {
  main { padding: 0.75rem; }
}
```

This single rule is what creates the visible gap between every rounded section card and the browser edge. Because all sections use `border-radius: var(--radius-card-lg)` (2rem), they float as distinct cards on the page rather than bleeding edge-to-edge. The padding grows slightly at 640px and above.

### Card border-radius system

The rounded-card aesthetic is achieved by layering `--radius-card` and `--radius-card-lg` across sections:

- **`--radius-card-lg` (2rem)** — outermost "page card" sections: `.hero`, `.stats`, `.foot`, and `.facilities` (which overlaps onto the programs section below it with `margin-top: -2.5rem`).
- **`--radius-card` (1.5rem)** — inner content cards: `.glass`, `.tcard`, `.coach`, `.badge-card`, `.modal-panel`, `.court`.
- **`--radius-pill` (62.5rem)** — anything that should be fully round: buttons, dots, badges, avatar borders.

The negative margin on `.facilities` (`margin-top: -2.5rem`) creates a deliberate overlap with the `#programs` section above it, reinforcing the card-stack visual rhythm. The same technique is used on `.stats` and `.foot` (`margin-top: 0.75rem` gaps).
