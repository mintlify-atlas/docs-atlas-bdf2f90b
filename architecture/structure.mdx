Baseline ships as a single self-contained artifact. There is no build step, no bundler, and no node\_modules directory — everything the browser needs is either inline in `index.html` or fetched at runtime from a CDN. This page maps every layer of that file, from the `<head>` metadata down to the runtime JavaScript engine.

## Top-level file list

| File | Role |
|---|---|
| `index.html` | The entire site: markup, inline `<style>`, and a `<script type="module">` block containing all animation logic, data arrays, and UI interactions. |
| `hero.jpg` | Fallback / preview image shown in the README. The live site uses a WebP served from `api.getlayers.ai`. |
| `README.md` | Developer guide — how to run locally, a section map, accessibility notes, and known limitations. |

## HTML document structure

### `<head>` contents

The `<head>` is minimal by design. Reading top to bottom:

```html
<meta charset="utf-8" />
<meta name="viewport" content="width=device-width, initial-scale=1" />
<title>Baseline — Tennis Club &amp; Academy</title>
```

A standard charset and viewport declaration, then a descriptive `<title>`.

```html
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
<link href="https://fonts.googleapis.com/css2?family=Onest:wght@400;500&display=swap"
      rel="stylesheet" />
```

Two `preconnect` hints warm up the Google Fonts connection before the stylesheet request, reducing perceived latency. The font request loads **Onest** at weights 400 and 500 with `display=swap` so the fallback system font renders immediately.

```html
<script type="importmap">
{ "imports": { "lenis": "https://cdn.jsdelivr.net/npm/lenis@1.1.18/+esm" } }
</script>
```

An [import map](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/script/type/importmap) resolves the bare specifier `"lenis"` to a versioned ESM build on jsDelivr. This is why the site **must be served over HTTP** — browsers block module imports on `file://` URLs.

```html
<style>
  /* ~500 lines of inline CSS */
</style>
```

Every style rule lives in a single `<style>` block in the `<head>`. There is no external stylesheet.

## Section map

`<main id="mainContent">` wraps all seven sections. The `inert` attribute is programmatically set on `<main>` when an overlay is open, blocking keyboard focus from reaching background content.

| `id` / selector | Element | Purpose |
|---|---|---|
| `#top` | `<section class="hero">` | Full-viewport hero: background image with parallax plate, sticky header, animated `<h1>`, tagline, hero slider card, and a membership stats widget. |
| `#trust` | `<section class="trust">` | Club credibility block: percentage badge, proof callout card, large ghost-text headline with word-clip animation, and the rotating coach carousel. |
| `#programs` | `<section class="programs">` | Training program list: four programs rendered from the `programs` data array as linked rows, each with a staggered spring reveal. |
| `#facilities` | `<section class="facilities">` | Court gallery: two-column layout with an intro blurb (word-fade animation) alongside two court cards with hover-scale effect. |
| `.stats` (no `id`) | `<section class="stats">` | Club numbers: four statistics from the `stats` array in a responsive 2→4 column grid, each with a staggered scroll reveal. |
| `#testimonials` | `<section class="testi">` | Member quotes: three testimonial cards from the `testis` array with spring-powered hover lift. |
| `#contact` | `<footer class="foot">` | CTA + sitemap + contact: booking call-to-action heading, three-column site navigation, social links, legal footer, and address block. |

## JavaScript engine overview

The entire script is a single `<script type="module">` block at the bottom of `<body>`. It imports Lenis via the import map, then sets up three distinct subsystems.

### a. Spring animation engine

The core animation primitive is a physics-based spring integrator. Every animated transition — overlay open/close, scroll reveals, hover effects — runs through this engine rather than CSS `transition` or a third-party library like GSAP.

**`Spring` class** — stores per-axis position (`x`), velocity (`v`), and target (`t`) values. Each call to `step(dt)` advances the simulation by one timestep using the classic spring formula:

```js
class Spring {
  constructor(el, from, to, cfg, apply){
    this.el = el; this.cfg = cfg; this.apply = apply;
    this.keys = Object.keys(to);
    this.x = {}; this.v = {}; this.t = {};
    for (const k of this.keys){
      this.x[k] = from[k] ?? to[k];
      this.v[k] = 0;
      this.t[k] = from[k] ?? to[k];
    }
    this.render(); springs.add(this);
  }
  to(target){ for (const k in target) this.t[k] = target[k]; this.active = true; }
  step(dt){
    let moving = false;
    for (const k of this.keys){
      const d = this.x[k] - this.t[k];
      if (Math.abs(d) < 0.0005 && Math.abs(this.v[k]) < 0.0005){
        this.x[k] = this.t[k]; this.v[k] = 0; continue;
      }
      moving = true;
      this.v[k] += (-this.cfg.tension * d - this.cfg.friction * this.v[k]) * dt;
      this.x[k] += this.v[k] * dt;
    }
    if (moving) this.render();
    return moving;
  }
  render(){ this.apply(this.x, this.el); }
}
```

`tension` and `friction` are the two tuning knobs. Higher tension = snappier response; higher friction = faster settling.

**`mkSpring` factory** — a convenience wrapper used throughout the file:

```js
function mkSpring(el, from, to, cfg, apply){
  return new Spring(el, from, to, {tension: cfg[0], friction: cfg[1]}, apply || transformApply);
}
```

The default `apply` callback maps the spring's value object onto CSS `transform` and `opacity`:

```js
const transformApply = (v, el) => {
  const parts = [];
  if ("x" in v) parts.push(`translateX(${v.x}${v.xUnit || "px"})`);
  if ("y" in v) parts.push(`translateY(${v.y}px)`);
  if ("scale" in v) parts.push(`scale(${v.scale})`);
  if ("rotate" in v) parts.push(`rotate(${v.rotate}deg)`);
  if (parts.length) el.style.transform = parts.join(" ");
  if ("opacity" in v) el.style.opacity = v.opacity;
};
```

**`tick` loop** — a single `requestAnimationFrame` loop drives every spring and the parallax system:

```js
let last = performance.now();
function tick(now){
  const dt = Math.min(0.032, (now - last) / 1000); last = now;
  for (const s of springs) s.step(dt);
  parallaxFrame();
  requestAnimationFrame(tick);
}
requestAnimationFrame(tick);
```

`dt` is capped at `0.032s` (≈ 30 fps floor) to prevent large jumps if the tab is backgrounded.

### b. Text reveal primitives

Four functions produce the animated text transitions seen on headings and body copy.

**`wordClips(el, text, opts)`** — splits a string on spaces and wraps each word in a `.clip > span` structure. The word starts `translateY(115%)` (below its clip mask) and the `.go` class transitions it to `translateY(0)`.

```js
function wordClips(el, text, opts={}){
  el.textContent = "";
  const words = text.split(" ");
  const nodes = words.map((w,i)=>{
    const clip = document.createElement("span");
    clip.className = "clip";
    if (opts.padBottom) clip.style.paddingBottom = opts.padBottom;
    const inner = document.createElement("span");
    inner.textContent = w;
    clip.appendChild(inner);
    el.appendChild(clip);
    if (i < words.length - 1) el.appendChild(document.createTextNode(" "));
    return {clip, inner};
  });
  return nodes;
}
```

**`playClips(nodes, opts)`** — triggers the reveal by adding `.go` to each clip node, staggered by `stagger` milliseconds. Respects `prefers-reduced-motion` by zeroing all durations when `RM` is `true`.

```js
function playClips(nodes, {stagger=120, base=0, dur=950, ease=EASE.easeOutExpo}={}){
  nodes.forEach((n,i)=>{
    n.clip.classList.remove("go");
    n.inner.style.transition = "none";
    void n.inner.offsetWidth; // force reflow to reset state
    n.inner.style.transition =
      `transform ${RM?0:dur}ms ${ease} ${RM?0:base + i*stagger}ms,
       opacity ${RM?0:dur}ms ${ease} ${RM?0:base + i*stagger}ms`;
    requestAnimationFrame(()=> n.clip.classList.add("go"));
  });
}
```

**`stackedLines(el, lines, opts)`** — same principle as `wordClips` but operates on full lines rather than words. Used for multi-line headings defined with `data-lines="Line one|Line two"`.

**`playStacked(el)`** — looks up the pre-built `stackedEls` registry by element reference and calls `playClips` with that element's stagger and duration settings. Called when the booking modal opens to animate its heading.

### c. Scroll-triggered reveals

Every element that animates on scroll uses `IntersectionObserver` with a consistent pattern:

```js
document.querySelectorAll("[data-inview]").forEach(el=>{
  const from  = JSON.parse(el.dataset.inview);
  const to    = JSON.parse(el.dataset.to);
  const cfg   = el.dataset.cfg.split(",").map(Number);
  const delay = +(el.dataset.delay || 0);

  const sp = mkSpring(el, from, to, cfg);

  const io = new IntersectionObserver(en=>{
    if (en[0].isIntersecting){
      setTimeout(()=> sp.to(to), RM ? 0 : delay);
      io.disconnect(); // fire once, then stop observing
    }
  }, {threshold: 0.15});

  io.observe(el);
});
```

The initial state (`data-inview`) is applied immediately so elements start hidden. When the threshold is crossed the spring target is set to `data-to` after an optional `data-delay` millisecond delay. `io.disconnect()` ensures the animation fires exactly once.

The same pattern is repeated inline for programs rows, stat items, testimonial cards, and the stacked heading elements, each with their own `threshold` and stagger timing.

## Overlay components

### Mobile menu — `#menu`

The full-screen navigation overlay is a sibling of `<main>`, not nested inside it.

```html
<div class="menu" id="menu"
     role="dialog"
     aria-modal="true"
     aria-label="Site menu"
     aria-hidden="true">
  <div class="menu-bd" data-close-menu></div>
  <div class="menu-panel"> … </div>
</div>
```

`aria-hidden="true"` is the default state. When opened, `openMenu()` sets it to `"false"` and also sets `mainContent.inert = true`, preventing keyboard and screen-reader users from reaching background content.

Three springs drive the open/close animation:

| Spring | From → To (open) | Config |
|---|---|---|
| `menuBdSp` (backdrop) | `opacity: 0 → 1` | tension 260, friction 30 |
| `menuPanelSp` (panel) | `opacity: 0, y: -24 → opacity: 1, y: 0` | tension 220, friction 28 |
| `menuLinkSps` (nav links × 4) | `opacity: 0, y: 28 → opacity: 1, y: 0` | tension 200, friction 26, staggered 70 ms |

Close plays the same springs in reverse. The Escape key, the backdrop, and any in-menu close button all call `closeMenu()`.

### Booking modal — `#modal`

The contact modal overlays the page with a blurred backdrop.

```html
<div class="modal" id="modal" aria-hidden="true">
  <div class="modal-bd" data-close-modal></div>
  <div class="modal-panel" role="dialog" aria-modal="true" aria-label="Book a visit">
    …
    <form class="cf" id="cform" novalidate> … </form>
    <div class="success" id="csuccess" hidden> … </div>
  </div>
</div>
```

Two springs handle open/close:

| Spring | From → To (open) | Config |
|---|---|---|
| `mBdSp` (backdrop) | `opacity: 0 → 1` | tension 240, friction 30 |
| `mPanelSp` (panel) | `opacity: 0, y: 28, scale: 0.96 → opacity: 1, y: 0, scale: 1` | tension 240, friction 26 |

On open, `playStacked()` is called to animate the modal's `data-lines` heading, and focus is moved to the first input after 120 ms. On close a 350 ms timeout resets the form to its initial state so it is clean on the next open.

Form submission is handled entirely client-side: after a 700 ms simulated delay the form is hidden and the `.success` confirmation panel is revealed with a green tick icon.

Any of the following triggers open the modal: the "Book a Visit" text button in the header, any `.pill` button with `data-open-modal`, or the "Book a Visit" button inside the mobile menu (which closes the menu first, then opens the modal after 220 ms).
