The Footer (`id="contact"`, `<footer class="foot">`) sits at the very bottom of the page and doubles as the primary conversion surface. It opens with a large booking call-to-action row, continues into a four-column sitemap with contact details, and closes with a bottom bar containing the copyright notice, social links, and legal links. The booking button in the footer (and in the mobile menu overlay) triggers the same contact modal that appears at the top of the page.

## HTML structure overview

```html
<footer class="foot" id="contact">

  <!-- 1. CTA row -->
  <div class="foot-cta">…</div>

  <!-- 2. Four-column sitemap -->
  <div class="foot-cols">…</div>

  <!-- 3. Bottom bar (copyright + social + legal) -->
  <div class="foot-bottom">…</div>

</footer>
```

## 1. Booking CTA area

The CTA row sits above a dividing hairline and contains the headline on the left and the "Book a Visit" pill button on the right. On mobile the two items stack vertically; on `640px+` they sit side by side aligned to the bottom edge.

```html
<div class="foot-cta">
  <div>
    <span class="eyebrow light"><i></i>Get started</span>
    <!-- data-lines splits "Ready to|play?" into two stacked clip lines -->
    <h2 data-lines="Ready to|play?"></h2>
  </div>

  <button
    class="pill light"
    data-open-modal
    data-inview='{"opacity":0,"y":20}'
    data-to='{"opacity":1,"y":0}'
    data-cfg="200,24"
    data-delay="150"
  >
    Book a Visit
    <svg viewBox="0 0 24 24" …><path d="M5 12h14M13 6l6 6-6 6"/></svg>
  </button>
</div>
```

The `data-open-modal` attribute is picked up by the global selector that wires every matching element to `openModal()`:

```js
document.querySelectorAll("[data-open-modal]").forEach(b =>
  b.addEventListener("click", openModal)
);
```

The CTA button also uses the standard inview spring system (`data-inview` / `data-to` / `data-cfg`), so it rises into view with a slight delay after the heading.

## 2. `#menuBook` button — chaining closeMenu and openModal

The "Book a Visit" button inside the mobile menu overlay (`id="menuBook"`) uses a dedicated event listener rather than `data-open-modal`, so it can **first close the menu, then open the modal** with a 220 ms gap between the two:

```js
document.getElementById("menuBook").addEventListener("click", () => {
  closeMenu();
  setTimeout(openModal, 220);  // wait for menu exit animation before opening modal
});
```

This prevents both overlays from being visible simultaneously and keeps the spring exit/entry animations from colliding.

## 6. The contact modal (`#cform` and `#csuccess`)

The modal is a fixed overlay rendered outside `<main>` and controlled by `openModal()` / `closeModal()`. It contains both the form and a success state; only one is visible at a time.

```html
<div class="modal" id="modal" aria-hidden="true">
  <div class="modal-bd" data-close-modal></div>
  <div class="modal-panel" role="dialog" aria-modal="true" aria-label="Book a visit">

    <!-- Header with animated headline -->
    <div class="modal-head">
      <div>
        <span class="eyebrow dark"><i></i>Book a visit</span>
        <h2 data-lines="Come see|the courts" data-stagger="90" data-dur="800"></h2>
      </div>
      <button class="iconbtn" aria-label="Close" data-close-modal>…</button>
    </div>

    <!-- Booking form -->
    <form class="cf" id="cform" novalidate>
      <div>
        <label for="f-name">Full name</label>
        <input id="f-name" name="name" type="text" placeholder="Alex Rivera">
      </div>
      <div>
        <label for="f-email">Email</label>
        <input id="f-email" name="email" type="email" placeholder="you@email.com">
      </div>
      <div>
        <label for="f-msg">What would you like to play?</label>
        <textarea id="f-msg" name="msg" rows="3"
                  placeholder="I'd love to try a private lesson on the clay courts…"></textarea>
      </div>
      <button type="submit" id="csubmit">Request a visit</button>
    </form>

    <!-- Success state (hidden until form submitted) -->
    <div class="success" id="csuccess" hidden>
      <div class="tick">
        <svg viewBox="0 0 24 24" …><path d="M5 13l4 4L19 7"/></svg>
      </div>
      <h3>Request received</h3>
      <p id="cmsg"></p>
      <button class="pill solid" data-close-modal>Done</button>
    </div>

  </div>
</div>
```

### Modal open / close springs

Two springs manage the modal entrance and exit:

```js
// Backdrop: fades in/out
const mBdSp = mkSpring(modalBd, { opacity: 0 }, { opacity: 1 }, [240, 30],
  (v, el) => el.style.opacity = v.opacity);

// Panel: fades + rises + scales
const mPanelSp = mkSpring(
  modalPanel,
  { opacity: 0, y: 28, scale: 0.96 },
  { opacity: 1, y: 0,  scale: 1    },
  [240, 26]
);
```

```js
function openModal() {
  modal.classList.add("open");
  modal.setAttribute("aria-hidden", "false");
  mBdSp.to({ opacity: 1 });
  mPanelSp.to({ opacity: 1, y: 0, scale: 1 });
  playStacked(modal.querySelector("[data-lines]")); // animate the headline
  lock();                                           // pause Lenis scroll
  setTimeout(() => document.getElementById("f-name").focus(), 120);
}

function closeModal() {
  mBdSp.to({ opacity: 0 });
  mPanelSp.to({ opacity: 0, y: 28, scale: 0.96 });
  modal.classList.remove("open");
  modal.setAttribute("aria-hidden", "true");
  unlock();
  // reset form after exit animation completes
  setTimeout(() => {
    cform.reset();
    cform.hidden = false;
    csuccess.hidden = true;
    csubmit.disabled = false;
    csubmit.textContent = "Request a visit";
  }, 350);
}
```

The `Escape` key closes both the modal and the menu:

```js
addEventListener("keydown", e => {
  if (e.key === "Escape") { closeModal(); closeMenu(); }
});
```

### Form submission and success state

The form's `submit` handler is entirely client-side. It disables the submit button, waits 700 ms (simulating a network round-trip), hides `#cform`, shows `#csuccess`, and personalises the confirmation message with the submitter's first name:

```js
cform.addEventListener("submit", e => {
  e.preventDefault();
  csubmit.disabled = true;
  csubmit.textContent = "Sending…";

  const first = (cform.name.value || "").trim().split(" ")[0] || "there";

  setTimeout(() => {
    cform.hidden = true;
    csuccess.hidden = false;
    document.getElementById("cmsg").textContent =
      `Thanks, ${first} — our team will be in touch to lock in your visit.`;
  }, 700);
});
```

<Warning>
The form submission is **simulated** — no data is sent to a server. To add real form handling, replace the `setTimeout` block with a `fetch()` call to your backend or a form service endpoint, and only show `#csuccess` on a successful response.
</Warning>
